# D1

Cloudflare's SQLite database.

**Use it when** the data suits tables and queries, such as lookups, joins and leaderboards. Use [Firestore](firestore.md) for documents, and [Durable Objects](durable-objects.md) for real-time.

**Source:** `nomp/server/`.

## Steps

1. Create the database, from `server/`:

   ```bash
   npx wrangler d1 create my-app
   ```

2. Add it to `server/wrangler.jsonc`, using the id that command prints:

   ```jsonc
   "d1_databases": [
     {
       "binding": "DB",
       "database_name": "my-app",
       "database_id": "<id>",
       "migrations_dir": "migrations"
     }
   ]
   ```

3. Add a script to `server/package.json`:

   ```json
   "db:migrate": "wrangler d1 migrations apply my-app --local"
   ```

4. Write migrations in `server/migrations/`, numbered and never edited after they're applied: `0001_init.sql`, `0002_add_scores.sql`.

5. Run `npm run types -w server`, so `c.env.DB` is typed.

6. Query with bound parameters, never by building SQL strings:

   ```ts
   const row = await c.env.DB.prepare('SELECT MAX(id) AS latest FROM scores WHERE user_id = ?1').bind(uid).first();
   ```

## Production

Apply each migration before deploying code that depends on it:

```bash
npx wrangler d1 migrations apply my-app --remote
```

## Cost

D1 bills by rows read and written, and a query without a suitable index reads every row.

- Add an index for each query that filters or sorts.
- Prefer static files for data that rarely changes. Nomp serves its categories as JSON files.
- Uploading seed data counts as rows written, so check the limits first.

## Check it works

- `npm run db:migrate -w server` applies cleanly on a fresh local database.
- `npm run build` passes, and a route that reads and writes works under `npm run dev`.
